# Diarization Improvement Plan: Venue Context, Voiceprint Matching & Speaker Source Type Upgrades

## Overview

This document describes a set of targeted upgrades to the civic_media speaker diarization
system. The existing pipeline (stages 1-6) is not being replaced — these changes extend
Stage 6 (Voiceprint Matching) and add supporting schema and UI to incorporate acoustic
venue context and per-segment speaker source type as confidence modifiers during speaker
identification.

**Two independent signals are being added:**

- **Venue context** — a property of the meeting location, set at the meeting level and
  inherited from the governing body default. Affects the matching candidate pool and
  confidence scoring.

- **Source type** — a property of the individual speaker's connection to the recording.
  A single meeting can have in-person speakers AND phone callers simultaneously. Set
  per segment during review via a UI toggle. Stored on the segment and voiceprint records.

The core principle for both: these are ranking and confidence signals, never hard exclusions.
A speaker appearing at a venue for the first time, or calling in for the first time, will
still be matched. The signals boost confidence for known patterns and surface them first,
degrading gracefully when history is sparse.

---

## 1. Database Schema Changes

### 1.1 New Table: venues

```sql
CREATE TABLE venues (
    id TEXT PRIMARY KEY,              -- UUID string, consistent with project schema
    name TEXT NOT NULL,               -- e.g. "Shasta County Board of Supervisors Chamber"
    acoustic_type TEXT NOT NULL,      -- enum: indoor_dry, indoor_reverb, outdoor,
                                      --        phone, radio_studio, mixed
    notes TEXT,                       -- optional free text
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

Seed with known venues at migration time (Board of Supervisors Chamber, City Council
Chambers, KCNR Studio, etc.) rather than creating them on demand.

---

### 1.2 Modify Table: governing_bodies (or equivalent meeting body table)

Add a default venue reference:

```sql
ALTER TABLE governing_bodies ADD COLUMN default_venue_id TEXT REFERENCES venues(id);
```

This single field handles the 95% case. All meeting types under a governing body
(regular sessions, special sessions, budget hearings, closed sessions, committee meetings)
inherit this default automatically. No per-meeting-type mapping needed.

---

### 1.3 Modify Table: meetings (or equivalent media/meeting table)

Add a per-meeting venue override:

```sql
ALTER TABLE meetings ADD COLUMN venue_id TEXT REFERENCES venues(id);
```

This field is nullable. When null, the system resolves the effective venue by walking up
to the governing body's default_venue_id. When set, it overrides the default for that
specific meeting only without affecting the governing body default.

**Resolution logic (Python helper):**

```python
def get_effective_venue(meeting) -> Venue | None:
    if meeting.venue_id:
        return meeting.venue
    if meeting.governing_body and meeting.governing_body.default_venue_id:
        return meeting.governing_body.default_venue
    return None
```

---

### 1.4 Modify Table: segments (or equivalent transcript segment table)

Add source type at the segment level. This is a per-speaker field — not per-meeting:

```sql
ALTER TABLE segments ADD COLUMN source_type TEXT NOT NULL DEFAULT 'in_person';
-- enum: in_person, telephone
```

Default is `in_person`. The value is set by the reviewer via UI toggle during review.
It persists immediately to the database on toggle and does not require a separate save
action. It is independent of the confirmation state — a segment can have source_type
set before, during, or after speaker confirmation.

---

### 1.5 Modify Table: voiceprints

Add venue context and source type at confirmation time:

```sql
ALTER TABLE voiceprints ADD COLUMN venue_id TEXT REFERENCES venues(id);
ALTER TABLE voiceprints ADD COLUMN source_type TEXT NOT NULL DEFAULT 'in_person';
-- source_type enum: in_person, telephone
```

When a user confirms a speaker segment, both the effective venue of the meeting AND
the segment's current source_type are captured on the voiceprint row. This creates
the historical record of "which people have appeared at which venues, and how they
were connected" that powers the matching pre-filter and source-type pool separation.

---

## 2. Stage 6 Voiceprint Matching Changes

The existing matching logic (Top-K=3 similarity scoring, coherence gate, confidence
thresholds) is preserved exactly. Venue context is layered on top as a pre-processing
step that modifies the candidate pool and adjusts scores before Top-K runs.

### 2.1 Venue-Aware Candidate Pool Construction

Before running Top-K similarity for an unconfirmed segment, build the candidate pool
in two tiers:

**Tier 1 — Venue-familiar candidates:**
Query voiceprints WHERE venue_id = current meeting's effective venue_id. These are
people confirmed to have appeared at this venue before. Group by person. Pass through
the existing coherence gate. These candidates receive a confidence boost of +0.05
applied to their final Top-K score.

**Tier 2 — Full pool fallback:**
All remaining voiceprints not represented in Tier 1. Standard coherence gate applied.
No boost applied.

**Matching runs against both tiers.** Results are merged and ranked by adjusted score.
Tier 1 results appear first when scores are tied.

```python
VENUE_FAMILIARITY_BOOST = 0.05  # configurable constant

def build_candidate_pool(segment, effective_venue_id):
    all_voiceprints = get_all_voiceprints_passing_coherence_gate()
    
    if effective_venue_id:
        venue_familiar_person_ids = get_person_ids_with_venue_history(effective_venue_id)
        tier1 = [vp for vp in all_voiceprints if vp.person_id in venue_familiar_person_ids]
        tier2 = [vp for vp in all_voiceprints if vp.person_id not in venue_familiar_person_ids]
    else:
        tier1 = []
        tier2 = all_voiceprints
    
    return tier1, tier2

def match_with_venue_context(segment, effective_venue_id):
    tier1, tier2 = build_candidate_pool(segment, effective_venue_id)
    
    results = {}
    
    # Score tier1 with boost
    for person_id, score in top_k_match(segment, tier1).items():
        results[person_id] = score + VENUE_FAMILIARITY_BOOST
    
    # Score tier2 at face value, don't overwrite tier1 results
    for person_id, score in top_k_match(segment, tier2).items():
        if person_id not in results:
            results[person_id] = score
    
    return sorted(results.items(), key=lambda x: x[1], reverse=True)
```

### 2.3 Source-Type Pool Separation

Source type is a stronger signal than venue familiarity and is handled differently —
it's a hard pool split rather than a boost. A telephone voiceprint and an in-person
voiceprint for the same person represent acoustically different recordings and should
not be compared interchangeably.

Before Top-K runs, filter the voiceprint pool to match the segment's source_type:

```python
def build_candidate_pool(segment, effective_venue_id):
    # Filter by source_type first — hard split
    all_voiceprints = get_all_voiceprints_passing_coherence_gate(
        source_type=segment.source_type  # 'in_person' or 'telephone'
    )
    
    if effective_venue_id:
        venue_familiar_person_ids = get_person_ids_with_venue_history(
            venue_id=effective_venue_id,
            source_type=segment.source_type
        )
        tier1 = [vp for vp in all_voiceprints if vp.person_id in venue_familiar_person_ids]
        tier2 = [vp for vp in all_voiceprints if vp.person_id not in venue_familiar_person_ids]
    else:
        tier1 = []
        tier2 = all_voiceprints
    
    return tier1, tier2
```

**Why this matters for telephone callers specifically:** Phone audio has narrowband
compression, carrier noise, and codec artifacts that produce embeddings that are
acoustically very different from the same person speaking in a room. Mixing these
into a single voiceprint pool introduces noise that degrades matching for both.
A phone caller's telephone voiceprints form their own clean pool used exclusively
when matching telephone-sourced segments.

**Fallback behavior:** If a person has no voiceprints for the current source_type
(e.g., a supervisor who has only appeared in-person but calls in for the first time),
they will not appear as a candidate in this matching pass. This is intentional —
the system surfaces unknown rather than making a low-confidence cross-type match.
The reviewer handles it as a new identification, which creates the first telephone
voiceprint for that person.

When a person has many voiceprints from one venue and few from another (e.g., a supervisor
with 200 chamber appearances and 6 Shasta Lake City Hall appearances), the small sample
from the outlier venue should not drag the primary centroid toward a different acoustic
profile.

The existing coherence gate (exclude voiceprints with cosine similarity to centroid < 0.6)
already handles gross outliers. For subtle acoustic drift, add venue-aware weighting to
the centroid computation used inside the coherence gate:

```python
def compute_weighted_centroid(voiceprints):
    # Count appearances per venue
    venue_counts = Counter(vp.venue_id for vp in voiceprints)
    total = len(voiceprints)
    
    # Weight each voiceprint inversely proportional to its venue's representation
    # Prevents a small venue cluster from punching above its weight
    weights = []
    for vp in voiceprints:
        venue_freq = venue_counts[vp.venue_id] / total
        # Venues with < 10% of total appearances get down-weighted
        weight = min(1.0, venue_freq / 0.10)
        weights.append(weight)
    
    weights = np.array(weights)
    weights = weights / weights.sum()  # normalize
    embeddings = np.array([vp.embedding for vp in voiceprints])
    return np.average(embeddings, axis=0, weights=weights)
```

This ensures a supervisor's canonical voiceprint stays anchored to their dominant
recording environment while still incorporating information from alternate venues.

## 3. Confirmation Flow Changes

When the user confirms a speaker segment, the voiceprint creation must capture both
venue and source type:

```python
def confirm_speaker_segment(segment_id, person_id):
    segment = get_segment(segment_id)
    meeting = segment.meeting
    effective_venue = get_effective_venue(meeting)
    
    voiceprint = Voiceprint(
        id=generate_uuid(),
        person_id=person_id,
        segment_id=segment_id,
        embedding=segment.embedding,
        venue_id=effective_venue.id if effective_venue else None,
        source_type=segment.source_type,   # 'in_person' or 'telephone'
        confirmed_at=datetime.utcnow()
    )
    db.add(voiceprint)
    
    # Existing logic: mark segment verified, trigger background re-match
    # No changes needed to the re-match trigger — it runs as before
```

The background re-match (triggered on every confirmation) already re-scores all
unverified segments in the meeting. It will automatically use the new venue-aware
matching logic on its next run since the function has been updated.

## 4. Meeting Settings UI Changes

The meeting edit/detail view should expose venue with clear source attribution.

### 4.1 Venue Display

Show the resolved venue with a visual indicator of its source:

- If meeting.venue_id is set → show venue name in primary style with a small "override"
  badge and an "X" to clear the override
- If meeting.venue_id is null and governing body has default_venue_id → show venue name
  in muted/secondary style with a small "default" badge
- If neither is set → show "No venue set" with a prompt to set one

Also display the venue's acoustic_type as a secondary line beneath the name so the user
understands the acoustic context being applied (e.g. "indoor_dry").

### 4.2 Venue Edit Control

A dropdown populated from the venues table. Options:

- All venues from the venues table
- "Use governing body default" option (clears the override, sets meeting.venue_id to null)
- "Add new venue..." option that opens an inline form to create a venue record on the spot

The dropdown should show both venue name and acoustic_type for each option so the user
can distinguish between similarly named venues.

### 4.3 Governing Body Default Venue

In the governing body settings view (wherever governing bodies are configured), add the
same venue dropdown to set default_venue_id. This is the one-time setup that means
routine meetings never need manual venue entry.

## 5. Speaker Candidate List UI Changes

Minor additions to the segment confirmation interface:

### 5.1 Venue Familiarity Badge

In the ranked candidate list shown during speaker review, add a small badge to candidates
whose boost came from venue familiarity. Label it "venue match" or use a location icon.
This helps the reviewer understand why a candidate ranked first — they've appeared here
before — building trust in the system's reasoning.

### 5.2 Score Display

Display the raw similarity score alongside the venue-adjusted score for transparency,
e.g. "0.89 → 0.94 (venue boost)". Optional but useful during the first few meetings at
a new venue to calibrate reviewer confidence.

## 6. Source Type Toggle UI (Review Page)

### 5.1 Button Placement and Appearance

On the segment review page, add two toggle buttons to the right of the existing
Ignore button in the segment action row. The buttons are mutually exclusive — selecting
one deselects the other. They behave as a two-state toggle, not independent checkboxes.

```
[ Ignore ]  [ In Person ]  [ Phone ]
```

Default state on page load: **In Person is selected** for all segments. This reflects
the correct default for the vast majority of segments in board meetings, council meetings,
and studio recordings. The reviewer only needs to act when a segment is a phone caller.

Visual treatment:

- Selected state: filled/solid button style (same as other active states in the existing UI)
- Unselected state: outlined/ghost button style
- Both buttons remain visible at all times — do not hide or collapse the unselected option
- "In Person" on the left, "Phone" on the right, consistent across all segments

### 5.2 Interaction Behavior

When the reviewer clicks **Phone**:
1. Phone button becomes selected (filled), In Person becomes deselected (outlined)
2. An immediate HTMX POST is sent to update `segment.source_type = 'telephone'` in the database
3. No additional save or confirm action is required — it commits on click
4. The background re-match for this meeting does NOT re-run on source_type change alone —
   source_type is captured at confirmation time. The re-match runs when a speaker is confirmed.

When the reviewer clicks **In Person** (to revert a Phone selection):
1. In Person becomes selected, Phone becomes deselected
2. An immediate HTMX POST updates `segment.source_type = 'in_person'`
3. Same immediate commit, no extra save needed

### 5.3 HTMX Endpoint

```
POST /segments/{segment_id}/source-type
Body: { "source_type": "telephone" | "in_person" }
Response: 200 OK (no body needed, swap is not required since only button state changes)
```

The endpoint updates the segment record only. It does not trigger re-matching, does not
affect voiceprints (source_type is captured on the voiceprint at confirmation time, not
retroactively from segment changes).

### 5.4 State Persistence on Page Load

When the review page renders, each segment's toggle buttons should reflect the current
`source_type` value from the database. If a reviewer leaves and returns, or the page
refreshes, all prior Phone designations are preserved correctly.

### 5.5 Visual Indicator in Segment List

In the segment list/timeline view, add a small subtle badge or icon to any segment
marked as `telephone` so the reviewer can see at a glance which segments are phone
callers without opening each one. A simple "📞" icon or a "TEL" badge in a muted style
next to the speaker label is sufficient.

## 7. Migration Notes

1. Create venues table
2. Seed initial venues (chamber, city hall, radio studio, etc.) with correct acoustic_type
3. Add default_venue_id to governing bodies and populate for known bodies
4. Add venue_id to meetings (nullable, no backfill required — historical meetings resolve
   to governing body default)
5. Add source_type to segments (NOT NULL DEFAULT 'in_person' — all existing segments
   backfill to in_person automatically, which is correct)
6. Add venue_id and source_type to voiceprints (nullable venue, DEFAULT 'in_person'
   source_type — existing voiceprints treat as venue-unknown in_person, Tier 2 matching)
7. Deploy updated Stage 6 matching logic with source_type pool split
8. Deploy source type toggle buttons on review page

No reprocessing of audio is required. No existing voiceprints or confirmed assignments
are modified. The in_person default means the system behaves identically to before for
all existing data — the telephone pool starts empty and builds as reviewers tag callers.

## 8. Future: Ground Truth Dataset

The combination of confirmed clean segments and tagged outlier/crosstalk segments
constitutes a labeled dataset of Shasta County civic audio. This corpus can be used to:

- Evaluate whether a future diarization model handles the specific acoustic environments
  better than pyannote 3.1 by scoring against confirmed ground truth
- Fine-tune an embedding model on civic meeting audio specifically, improving performance
  on the exact speaker characteristics, microphone setups, and speaking styles in the library
- Run A/B comparisons between the current Top-K approach and newer matching strategies
  without risking production data

No action needed now. The data is accumulating passively with every confirmation.
Preserve the venue_id and confirmation metadata on all voiceprint records so this
context is available for any future evaluation run.
